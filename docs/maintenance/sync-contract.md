# 公开文档同步约定

## 来源与写入边界

维护者仅在独立文档工作树、专属分支中写本目录以下六份文件：`README.md`、`public-status.md`、`technical-index.md`、`approved-decisions.md`、`known-issues-and-next.md`、`sync-contract.md`。本目录为派生导航，正式状态、决定、冻结设计和产品实现继续由原负责人维护。工作树和会话须按项目实际 hook 流程准入；创建目录或复制配置不构成准入。

公开来源使用固定提交中的文件、公开 Issue／PR／CI 及其采集时间；可变任务状态注明采集时刻。工程 SHA、文档来源 SHA、新文档交付 SHA 分别记录，测试结果只归属于其实际 SHA 和范围。内部材料只用于本地核对，不直接复制到公开内容。没有公开依据的细节保留待核。

## 每次执行

1. 成功完成一次公开仓库只读请求，记录 main SHA、采集时间及目标分支。失败时保留上次可信快照，向维护回执标明离线／待核，不刷新成功时间或宣称最新。
2. 核准六路径、唯一文档写者和实际工作树准入；只比较上次来源后有实质变化的公开内容。接口、架构和数据结构仅随已合并变化定向更新；只有日期变化不提交。
3. 在固定候选中核查文件白名单、链接目标、来源与状态分类、隐私与凭据。公开差异仅含获准项目摘要；排除会话、内部标识、机器配置、凭据、其他项目和本地原始证据。遇到不明内容先留在公开差异之外。
4. 固定候选交独立只读审查，按现有要求取得必要 CI 与 PR 审查结果。失败保留实际记录并修正同范围文档；保持产品门禁、CI 配置和预算。任何合并前的实质修改都须重新核对实际候选。
5. 合并后分别回读 PR 合并结果、实际 main SHA、main CI 及六文件内容。只安全同步本维护者的文档工作树。其他负责人的本地同步、其他目标的发布和定时安排分别由对应负责人确认；一个目标成功不代签其他目标。

## 同一正式事件与职责协作

同一批次临近正式交付时，维护者先准备来源与最小差异，待对应公开来源和正式记录齐备后合并为一次派生同步；不将等待文档同步或后续维护反加为产品交付门。普通批内返修及客观依赖完成后的下一步沿既有职责推进，不为普通确认重复等待；一个问题保留一个负责人跟至结果，重复阻塞复用同一证据包。

源与语义未变时按实际影响复用有效证据，只验证变化影响。配置或报告改进的批准、实施、生效与效果分别记录，计划不写成部署事实；真实范围、权限、合同、重大质量或平台例外仍由原有负责人处理。本约定不新增角色、权限或框架。

## 冲突、幂等与失败补偿

每次先核对源基线和目标内容；相同公开事实及相同内容返回无变化，不产生空提交或新增工程事件。已合并结果按 PR／SHA 去重，发送或创建结果不明时先回读，避免重复 PR。

发现其他写者修改、目标偏离或未提交内容时停止覆盖，保留自己的候选并交负责人协调。远端 main 前进后重新比较所选基线，必要时更新本分支、检查和审查；不重置其他工作树，不覆盖正式文档或冻结包。

PR 创建、CI、合并、main 核验与本地同步逐项记录成功、失败、待核或结果不明。部分失败保留成功目标及原回执，只重试缺失步骤；无法安全继续时报告精确动作、目标、原因和已完成范围。文档同步失败不能回退工程交付状态，也不能通过改旧证据或清理用户数据补偿。

## 文档专属 CI

采用已合并的现行六路径分类规则：仅既有普通维护文档的非空修改才走 docs-only，runtime 记为 not_run。分类只核差异、路径与文件身份，不代替实际来源、链接、Markdown／差异和隐私检查。若远端意外选择 full，保留结果并停止该发布动作，不扩分类器、不跳过门禁、不为文档重跑浏览器。旧运行失败保持原结论；没有实质差异不空提交或重跑凑证明。

正式交付、后续准备与独立工具维护分开记录；技术导航只随已发布接口和存档结构作定向更新。动态入口的准备状态不证明代码已开工，已交付工程也不证明父端其他同步目标已完成。
